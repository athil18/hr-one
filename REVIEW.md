# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Grace period logic checked `minutes > 10` after integer floor division instead of checking elapsed seconds > 600. | Input punch-in at `09:40:01` for shift `09:30`: `int(601 / 60) = 10`. `10 > 10` evaluates `False`, incorrectly returning `0` instead of `10` (violates R2). | Checked `(punch_in_ist - shift_start_dt).total_seconds() > 600` before applying floor division `diff_sec // 60`. |
| 2 | `compute_late_minutes` (lines 33–37) | Naive `.replace(hour=h, minute=m)` replaces UTC hour directly with IST shift hour without timezone conversion. | UTC punch-in `04:05:00` (IST `09:35:00`) replaced to `09:30:00` in UTC, producing a negative delta or arbitrary timestamps. | Converted `punch_in` to IST timezone (`Asia/Kolkata` / `UTC+05:30`) and constructed `shift_start_dt` in IST before computing difference. |
| 3 | `compute_work_hours` (lines 40–42) | Used Python's built-in `round()`, which performs IEEE 754 round-to-even (banker's rounding) and float rounding. | For 2.675 hours (9,630 seconds), `round(2.675, 2)` returns `2.67` instead of `2.68` (violates R4 requirement for half-up rounding). | Used `decimal.Decimal` with `ROUND_HALF_UP`: `(Decimal(diff_sec) / Decimal(3600)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44–48) | Missing 30-minute minimum qualification threshold. Returns overtime for any positive minutes. | Punch-out 20 minutes after shift end returned `20` instead of `0` (violates R3: "counted only when that is >= 30; otherwise 0"). | Calculated `mins = diff_sec // 60` and returned `mins if mins >= 30 else 0`. |
| 5 | `compute_overtime` (lines 44–48) | Overnight shifts (`shift_end <= shift_start`) constructed `shift_end` on the attendance date instead of the following calendar day. | Overnight shift `22:00 - 06:00` on `2026-07-06` evaluated `shift_end` at `2026-07-06 06:00` (16 hours prior), computing huge false overtime. | Added check: if overnight, `shift_end_date = attendance_date + timedelta(days=1)`. |
| 6 | `compute_overtime` (lines 44–48) | Subtracted timezone-aware datetime `end` from potentially offset-naive datetime `punch_out`. | Comparing offset-naive and offset-aware datetimes throws unhandled `TypeError: can't compare offset-naive and offset-aware datetimes`. | Ensured both operands are timezone-aware in IST before subtraction. |
| 7 | `health` (lines 72–74) | Returned unconditional `{"status": "ok"}` without verifying database connectivity. | Endpoint returned 200 even when MongoDB server was unreachable or down (violates contract: 200 only when MongoDB answers, else 503). | Executed `client.admin.command("ping")` in a try/except block; raised `HTTPException(503, "Database unavailable")` on failure. |
| 8 | `create_employee` (lines 77–86) | Check-then-insert pattern without unique database index permitted duplicate `emp_code` under concurrent requests. | Concurrent `POST /employees` requests with identical `emp_code` both passed `find_one()` and created duplicate records. | Created a unique index on `employees.emp_code` at startup and handled `DuplicateKeyError` by raising 409 Conflict. |
| 9 | `create_employee` (lines 77–86) | Missing validation that `shift_start` must differ from `shift_end`. | Request with `shift_start: "09:30", shift_end: "09:30"` created an invalid employee record instead of returning 422. | Added validation check `if body.shift_start == body.shift_end: raise HTTPException(422)`. |
| 10 | `create_employee` (lines 77–86) | `created_at` stored local naive datetime and returned unformatted datetime rather than epoch milliseconds. | Response serialized `created_at` as ISO string or datetime object violating `EpochMillis` integer contract. | Stored whole-second truncated UTC datetime and serialized `created_at` as integer epoch milliseconds. |
| 11 | `list_employees` (lines 88–97) | Off-by-one pagination bug: `skip = page * page_size` skipped the entire first page when `page=1`. | Querying `GET /employees?page=1&page_size=20` skipped records 1–20 and returned records 21–40. | Changed skip calculation to `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (lines 88–97) | Total count ignored the `department` filter: `total = db.employees.count_documents({})`. | Querying `GET /employees?department=Sales` returned total count of all company employees rather than Sales employees (violates R10). | Changed to `total = db.employees.count_documents(q)`. |
| 13 | `list_employees` (lines 88–97) | Query results were not sorted by `emp_code` ascending. | Returned documents in arbitrary natural insertion order violating OpenAPI specification. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 14 | `punch_in` (lines 99–122) | Check-then-insert pattern allowed duplicate punches for the same employee and date under concurrent requests. | Concurrent punch-in requests at the same instant both succeeded, inserting multiple documents for the same `(emp_code, date)`. | Created a unique compound index on `("emp_code", 1), ("date", 1)` on `attendance_logs` and caught `DuplicateKeyError` to return 409. |
| 15 | `punch_in` (lines 99–122) | Calculated calendar date using local system timezone `datetime.fromtimestamp()` without handling overnight shifts. | Punch-in at `00:30 IST` for a `22:00 - 06:00` overnight shift was assigned to date D instead of shift start date D-1 (violates R1). | Implemented R1 overnight rule in IST: if punch-in IST time < `shift_end`, attendance date is `cur_date - 1 day`. |
| 16 | `punch_in` (lines 99–122) | Unchecked employee lookup resulted in unhandled `KeyError: 'shift_start'` (500 Internal Server Error) when `emp_code` was not found. | Punch-in with non-existent `emp_code` crashed with 500 instead of returning 404 Not Found. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 17 | `punch_in` (lines 99–122) | Status field accepted any arbitrary string without validation. | Punch-in accepted invalid status values like `"VACATION"` or `"ABSENT"`. | Restricted status validation in request model to `^(PRESENT|WFH|ON_DUTY)$`, returning 422 for invalid inputs. |
| 18 | `list_attendance` (lines 124–151) | In-memory loading `docs = list(db.attendance_logs.find(q))` and Python sorting `docs.sort()`. | At 100,000 documents, loading all documents into application memory caused severe memory consumption and latency. | Delegated sorting and pagination directly to MongoDB: `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. |
| 19 | `list_attendance` (lines 124–151) | Missing range validation when `date_from > date_to`. | Querying `GET /attendance?date_from=2026-08-10&date_to=2026-08-01` executed empty query instead of returning 422. | Added validation `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |
| 20 | `list_attendance` & `punch_in` (lines 119–120, 149) | Injected internal `doc["id"] = str(_id)` into returned records, violating the API contract. | Response contained an `id` field which is prohibited by OpenAPI `AttendanceRecord` schema. | Removed `id` injection and ensured `_id` is never serialized or returned. |
| 21 | Instants truncation (R1) | Did not truncate instants to whole seconds before calculations and persistence. | Punch at `09:40:00.900` retained fractional seconds affecting work hours and late minute calculations. | Truncated all instants: `(ms // 1000) * 1000` and `microsecond = 0` per Rule R1. |

## Examined and Decided Not a Defect

1. **`page_size` defaults and limits:** Default of 20 and max of 100 matches Rule R10.
2. **Identification via `emp_code`:** Absence of synthetic database IDs in routes is intentional per design specifications (`emp_code` is the business key).
3. **Natural compound key for attendance:** Addressing attendance records by `(emp_code, date)` without an ObjectId is by design and strictly adheres to `DATA_MODEL.md`.
